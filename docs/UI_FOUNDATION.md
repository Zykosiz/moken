# Moken — UI Foundation

## Core Visual Identity

Moken's interface uses a fractured-glass visual language across dialogue, combat, menus, selectors, status displays, and transitions.

The goal is not to imitate a smashed window literally. The UI should feel as though reality itself is held together through translucent shards, hairline fractures, and overlapping panes.

This visual language connects directly to the Horrors and their black-mirror distortion without making every normal interface screen feel hostile or corrupted.

---

## Normal UI State

Outside Horror influence, the UI should feel:

- Translucent
- Light
- Maritime
- Weathered rather than broken
- Elegant rather than aggressive
- Irregular without becoming chaotic

Preferred material references:

- Frosted lighthouse glass
- Sea glass
- Old lantern panes
- Spyglass lenses
- Bottle glass worn by salt and time
- Subtle reflections from water and sky

The normal interface should use pale, desaturated glass tones with restrained blue, green, or grey tinting. Fine scratches, edge wear, and internal cracks are allowed, but they should remain subtle enough that the UI feels functional and calm.

The interface should not default to black, heavily damaged, or horror-coded presentation.

---

## Shape Language

UI panels should avoid perfect rectangles where practical.

Instead, major panels may be built from:

- One dominant irregular pane
- Smaller overlapping shards
- Slightly angled edges
- Broken corners
- Asymmetrical silhouettes
- Thin fracture lines that help divide information

The shapes should still align to a clear layout grid. The interface may look fractured, but the information hierarchy must remain deliberate.

Irregularity is a visual treatment, not permission for poor alignment.

---

## Dialogue UI

Dialogue should use character portraits with fractured, semi-transparent glass framing.

Suggested structure:

- Character portrait held inside an irregular glass pane
- Dialogue text placed in a wider overlapping pane beside or beneath the portrait
- Speaker name integrated into a smaller shard or fracture segment
- Subtle edge refraction or frosted treatment behind text
- Minimal decorative fragments around the main readable area

The portrait and text should feel connected as one assembled glass composition rather than two unrelated boxes.

Dialogue readability takes priority over transparency. Background dimming, blur, or opacity should increase automatically when the scene behind the text is visually busy.

---

## Battle UI

The battle interface should use the same fractured-glass language rather than a separate art direction.

A party status element may contain:

- Character portrait in a compact shard frame
- HP directly to the right of the portrait
- Pistol resource, bullet count, reload state, or equivalent combat resource below or beside HP
- Status effects attached as smaller fragments
- Turn readiness or selection feedback expressed through light moving across the glass rather than large glowing outlines

Menus, commands, targets, and selectors should appear as related shard clusters.

The layout must remain compact and readable. Decorative glass pieces should never occupy more visual space than the information they support.

---

## Menus and Navigation

Inventory, settings, save/load, equipment, and future party menus should all use the same material language.

Large menu screens may resemble several panes assembled into one fractured surface. Categories and tabs can occupy separate shards that visually interlock.

Selection states should rely on a controlled combination of:

- Increased opacity
- Sharper edge highlights
- A moving reflection
- Slight separation from neighboring panes
- A restrained sound cue

Do not rely only on color changes for selection clarity.

---

## Horror Influence

When a Horror arrives, the normal UI does not change into a completely unrelated design.

Instead, the existing glass interface becomes corrupted.

Possible Horror-state changes:

- Fractures spread through existing panes
- Reflections darken or move incorrectly
- Shards subtly drift out of alignment
- Text or portraits briefly refract through the wrong angle
- Familiar panes become mirror-black
- Tiny reflections show impossible spaces, shapes, or expressions
- UI transition timing becomes slightly unnatural
- Some edges appear sharper or more dangerous

The player should recognize that the same interface is being rewritten by the Horror.

The transformation should escalate with the encounter rather than applying maximum distortion immediately.

---

## Lighthouse Connection

The glass visual language also belongs naturally to the world outside the Horrors.

The starting lighthouse gives the interface a grounded source of inspiration:

- Fresnel lenses
- Lantern glass
- Reflected beacon light
- Worn maritime equipment
- Light passing through imperfect panes

This allows the UI to symbolize both damage and guidance.

The normal UI represents light passing through a fractured world. The Horror-state UI represents those fractures becoming active and hostile.

---

## Readability Rules

The fractured-glass identity must never reduce basic usability.

Hard rules:

- Text must sit over sufficiently opaque or blurred surfaces
- Important numbers must not cross fracture lines
- Decorative cracks must not resemble letters, icons, bars, or cursor states
- HP, resources, reload state, and selection states must be readable at a glance
- Irregular shapes must preserve consistent spacing and alignment
- Every screen must remain usable without relying on motion effects
- Horror distortion may unsettle the player, but it must not conceal required gameplay information
- Accessibility options should be able to reduce refraction, motion, transparency, and visual distortion

---

## Production Principles

The system should be built from reusable components rather than unique artwork for every screen.

Recommended component set:

- Scalable glass panel base
- Several corner and edge shard variants
- Reusable fracture overlays
- Portrait frame variants
- Selection/highlight state
- Normal reflection material
- Horror reflection material
- Opacity and background-blur controls
- Reduced-motion and high-readability variants

Nine-slicing or equivalent scalable construction should be used where possible, but the repeated shapes should be varied enough that every panel does not reveal the same fracture pattern.

The visual system should support gradual Horror corruption through material and animation changes without requiring every UI screen to be rebuilt.

---

## Canon Rules

- Fractured glass is Moken's primary UI language.
- Normal UI is translucent, maritime, weathered, and readable rather than dark or aggressively broken.
- Dialogue, battle, menus, status elements, selectors, and transitions should belong to the same visual family.
- The Horror state corrupts the existing UI instead of replacing it with an unrelated interface.
- The lighthouse and its glass provide a grounded thematic source for the design.
- Readability always takes priority over decorative fracture detail.
- The interface may be asymmetrical, but its layout and information hierarchy must remain precise.
- The UI should suggest that light is passing through a world that has already begun to crack.
